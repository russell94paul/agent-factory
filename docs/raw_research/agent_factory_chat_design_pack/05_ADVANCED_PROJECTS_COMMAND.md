# 05 — Advanced Projects Command (“Black Site”)

## Mission

A persistent autonomous cross-team organization that continuously asks:

> Given current Commander's Intent and everything the organization has learned, what is the highest-leverage thing we could improve next?

This is the Army-themed successor to the earlier “Lab / Prometheus” concept.

## Inputs

### Engineering
- bugs
- incidents
- code reviews
- repeated workflow friction
- clever fixes
- architecture bottlenecks

### Product
- feature requests
- user behaviour
- abandoned ideas
- adoption gaps
- telemetry

### Sales
- objections
- lost deals
- requested capabilities
- pricing/willingness-to-pay signals

### Support
- recurring questions
- churn reasons
- pain-point clusters
- edge cases

### Agents
- execution traces
- failures
- recurring failures
- successful strategies
- disagreements
- repeated tool sequences
- unused discoveries
- human interventions

### Research
- papers
- open-source systems
- models
- tools
- HCI research
- organizational science
- competitors

## Internal units

Possible configurable team:
- Research Commander
- Signal/Opportunity Scout
- Evidence Analyst
- Skeptic / Red Cell
- Experiment Designer
- Prototype Engineer
- Evaluator
- Architecture Mapper
- Field-Trial Officer
- Doctrine Curator

## Loop

Observe
→ connect signals
→ cluster opportunities
→ estimate leverage
→ research
→ actively seek disconfirming evidence
→ design experiment
→ prototype in sandbox
→ war-game
→ field trial / canary
→ promote / modify / kill
→ update doctrine and memory

## Campaign objective

Never optimize “make company better”.

Use an explicit success criterion, for example:
- revenue,
- delivery speed,
- quality,
- feature demand,
- cost per accepted outcome,
- customer satisfaction,
- recurrence reduction.

Constraints should also be explicit.

## Opportunity / Leverage Board

Avoid fake single-number precision. Use multi-objective/Pareto comparison over:
- expected outcome delta,
- evidence strength,
- reach/frequency,
- confidence,
- implementation cost,
- risk,
- time,
- reversibility,
- strategic fit.

## Gamified mechanics

- throw an idea/failure/observation into Advanced Projects Command,
- autonomous clustering,
- high-leverage candidate becomes a “priority operation”,
- experiment crews spawn,
- war-game bracket,
- field trial,
- promote as doctrine,
- failed experiment enters the “failed experiment graveyard” with its learning value.

## Company-wide contribution mechanics

### Drop Your Loot
At mission end:
- reusable finding,
- shortcut,
- failure mode,
- idea,
- weird behaviour,
- nothing useful.

Agents structure the contribution automatically.

### Cross-Team Combination
Multiple independent signals combine into stronger evidence.

### Micro-Quests
Ask humans questions agents cannot resolve cheaply:
- “What repetitive thing did you do this week?”
- “What process makes no sense?”
- “Find something another team does better.”
- “What should we delete?”

## Autonomy boundary

Research, simulation, sandbox prototyping, and low-risk evaluation may become highly autonomous.

Production deployment, significant spend, customer communication, pricing, security-sensitive changes, or irreversible actions should remain governed by Rules of Engagement.
