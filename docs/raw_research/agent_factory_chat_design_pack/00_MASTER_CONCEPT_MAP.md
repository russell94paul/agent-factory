# 00 — Master Concept Map

## A. Primary Product Paradigm — CURRENT / CORE

### Agentic IDE
The core product is not a dashboard for agents. It is an **IDE for directing artificial organizations**.

Primary operator responsibilities:
- express intent,
- inspect state,
- coordinate teams,
- manage autonomy,
- resolve exceptions,
- compare strategies,
- intervene,
- evaluate outcomes,
- learn from execution.

Primary objects:
- campaigns,
- operations/missions,
- objectives,
- organizations,
- teams,
- agents,
- context/intelligence,
- decisions,
- artifacts,
- communications,
- approvals,
- evaluations,
- outcomes,
- recurring failures,
- doctrine.

### Mission Command Console
The serious, dense, precision-first interface. This should come before the animated world.

### Alternate Army Command World
A second projection over the same domain state. It should be spatial, animated, witty, social, and highly gamified, while still accelerating actual operational work.

## B. Interaction Paradigm — CURRENT

### Spatial Command Language
The world is faster when:
- **location** encodes ownership/domain,
- **distance** encodes relationship or urgency,
- **movement** encodes workflow,
- **formation** encodes execution topology,
- **front line** encodes priority,
- **supply lines** encode context/tools/permissions/compute,
- **signals** encode communication,
- **fog of war** encodes uncertainty,
- **threats** encode failure/risk,
- **after-action reports** encode learning,
- **war games** encode evaluation,
- **doctrine** encodes validated reusable patterns.

### Semantic Zoom
Company → theatre → campaign → operation → task force → squad → agent → task/tool call/file.

### Typed Commands
World gestures must compile to typed commands handled by the same backend as the normal UI.

## E. Autonomous Improvement Organization — CURRENT / EXPERIMENTAL

### Advanced Projects Command / “Black Site”
Persistent autonomous organization that consumes:
- successes,
- failures,
- recurring failures,
- agent traces,
- human interventions,
- customer demand,
- product telemetry,
- support issues,
- sales evidence,
- architecture bottlenecks,
- external research,
- cost signals,
- repeated work patterns.

It asks:
> Given Commander's Intent, what is the highest-leverage change the organization can make next?

Loop:
Observe → connect signals → rank opportunities → research → challenge → prototype → war-game → field trial → promote/kill → learn.

## F. Organizational Learning — CORE

### Failure Recurrence
Failure rate alone is insufficient.

Track:
- Recurring Failure Rate (RFR)
- Recurring Incident Count
- Failure Family Frequency
- Time to Recurrence
- Post-Fix Recurrence Rate
- Preventable Recurrence Rate
- Doctrine Effectiveness
- Knowledge Retrieval Failure
- Context Delivery Failure
- Execution Against Known Doctrine
- Structural Prevention Success

### Failure Families
Group semantically equivalent incidents by root cause rather than exact error string.

### Learning Chain
Knowledge existed → retrieved? → delivered? → understood? → followed? → prevention worked?

The goal is not merely “fewer failures.” It is:
> Does the Army stop making the same mistakes?

## I. Design Evolution / Superseded

### Zeus/Olympus World — SUPERSEDED FOR UI THEME
The Zeus mythology exploration produced useful architectural naming patterns, but the user selected a **full Army/Mission Command theme** for the world.

Retain Zeus artifacts only as reference for:
- service-to-world mapping,
- role identity,
- world vocabulary design,
- consistent thematic semantics.

Do not treat Zeus naming as current UI direction.
