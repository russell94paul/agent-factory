# 01 — Primary Agentic IDE / Mission Command Console

## Product thesis

The first UI is the serious one.

It should make one engineer substantially better at directing:
- multiple missions,
- multiple teams,
- multiple agents,
- approvals,
- failures,
- context,
- experiments,
- deployments,
- outcomes.

The alternate Army world should reuse this same state model.

## Primary surfaces

### 1. Command
Universal command bar:
- build this,
- investigate,
- delegate,
- assemble team,
- summon specialist,
- challenge,
- compare,
- replay,
- reorganize,
- evaluate,
- promote,
- rollback.

### 2. Campaigns
Groups related operations under a strategic objective.

### 3. Operations
Outcome-bound missions with:
- objective,
- constraints,
- owners,
- team topology,
- dependencies,
- risk,
- budget,
- GREEN criteria,
- current status.

### 4. Teams / Force Structure
View and modify organization topology.

### 5. Agents
Inspect:
- role,
- model,
- tools,
- context,
- budget,
- capabilities,
- mission history,
- certifications,
- failure/recurrence profile.

### 6. Communications
Consequential decisions, blockers, handoffs, evidence, distress/help.

### 7. Intelligence
Mission-relevant knowledge assembled from wiki, memory, prior missions, repos, telemetry, and external research.

### 8. Evaluation
Champion/challenger, regression checks, outcome metrics.

### 9. Intervention
Pause, hold, reroute, redeploy, replace, escalate, rollback.

### 10. Replay
Causal execution trace and counterfactual restart from any point.

## Primary design metric

Not “how many agents can the UI display?”

Measure:
- human coordination time,
- operator interventions,
- navigation/context switches,
- time-to-understand,
- time-to-correct,
- missed blockers,
- duplicated work,
- task completion time,
- cost per accepted outcome,
- recurrence avoided.

The product wins when one engineer can supervise a much larger artificial organization without attention becoming linear in agent count.
