# Recommended Implementation / Research Sequence

The user does not want to implement the world yet. This is the order to research and later prototype.

## Phase 0 — Preserve primary UI priority

Finish / harden the normal Agentic IDE / Mission Console concepts first.

Required substrate:

- typed mission state
- agent/team state
- event stream
- context/evidence model
- approvals
- evals
- metrics
- replay/audit

## Phase 1 — Shared domain model

Before 3D/2D world work:

- recursive OrganizationNode
- service designations
- formation schema
- failure families / recurrence ledger
- typed events
- typed commands
- projection API

## Phase 2 — Benchmarkable Army interactions

Prototype low-cost versions of:

1. Surveillance View
2. Target Lock
3. Reinforcement Router
4. Logistics Health
5. Smart Handoff
6. Collision Control

Compare them directly against a conventional dense UI.

## Phase 3 — Formation / tactical interactions

Research/prototype:

- Formation Compiler
- Tactical Zoom
- Frontline prioritization
- Fog of War
- Signals Network

## Phase 4 — Learning / doctrine

Implement conceptually:

- AAR
- Failure Family
- RFR / PRR
- Doctrine lifecycle
- War Games
- Workflow Compression

## Phase 5 — Advanced Projects Command

Only once evidence, metrics and eval infrastructure are mature enough to support controlled improvement.

## Phase 6 — Fully animated world

Then invest in:

- persistent base
- avatars
- team buildings
- environmental state
- world presence
- social/gamified features
- animation polish

## Graduation criteria for a world feature

Suggested research thresholds:

- >=25% faster completion for a representative task, OR
- >=40% fewer navigation/context switches, OR
- significantly fewer missed anomalies / mistakes, OR
- materially better situation awareness, OR
- a new capability not available in dense UI.

A feature can still survive as optional culture/social functionality, but should not displace a faster serious control.
