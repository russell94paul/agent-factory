2. PRODUCT MODEL

CELL OS is not a graphical wrapper around agent chat.
The user expresses an outcome, constraints and authority boundaries.
CELL OS should:
understand intent
 create a Mission Contract
 compile an Operative Cell
 allocate context/capabilities/resources
 execute work
 supervise activity
 involve the human only where appropriate
 verify outcomes with evidence
 preserve artifacts and decisions
 replay execution
 learn
 improve future organizational configurations
The primary executable/certifiable organizational primitive is the:

CELL

A Cell may contain multiple:

OPERATIVES

plus deterministic workers, capabilities, memory/context mounts, evaluators, policies and gates.

6. CORE UX DOCTRINE

Non-negotiable:

        · Agent narrative is not evidence.

                                                                         4
        · Done does not equal Verified Success.
        · Work state, runtime state and assurance state remain distinct.
        · Context travels with the mission.
        · Evidence and artifacts are first-class objects.
        · Human attention is a scarce resource.
        · Autonomous events never steal keyboard focus.
        · Preserve drafts, scroll position, selected objects and spatial memory.
        · Important objects should not randomly reorder while the user is reading.
        · Progressive disclosure beats telemetry walls.
        · Critical information cannot exist only on hover.
        · Keyboard, mouse, natural language and voice should use one underlying command system.
        · Consequential natural-language commands show a structured action preview.
        · Graphs are used when topology or dependency is actually the question.
        · Mobile is designed for supervision rather than becoming a tiny remote terminal.

10. MOTION SYSTEM

Motion should communicate only:

        · orientation
        · causality
        · status
        · continuity
        · feedback

Suggested timing system:

        · press ~90ms
        · hover ~120ms
        · tooltip ~130ms
        · popover ~160ms
        · menu/tab ~180ms
        · inspector ~240ms
        · consequence sheet ~260ms
        · workspace continuity ~320ms
        · complex deliberate visualization <500ms

State transitions occur in place.

Do not make Working  Waiting  Done cause cards to jump around.

Pearl glisten may exist only in peripheral/empty chrome and should disappear during focused work.
Prefer event-linked shimmer--for example, a single restrained highlight when a mission becomes
Verified--over constant decorative movement.
Explicitly design reduced-motion behavior.

11. HOVER AND OVERLAY GRAMMAR

Use:
Tooltip  short supplemental information
Popover  compact metadata or quick action
Inspector  deep state, relationships, provenance, context, versions, evidence and actions
Modal  bounded synchronous form
Consequence Sheet  consequential/high-risk action
Never hide a required instruction behind a tooltip.
Hover should reveal detail without causing layout shifts, card scaling or visual noise.
