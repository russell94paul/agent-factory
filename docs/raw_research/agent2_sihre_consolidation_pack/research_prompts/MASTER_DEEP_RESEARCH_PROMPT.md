# MASTER DEEP RESEARCH PROMPT
## Beyond the Standard AI Agent: SIHRE, Recursive Cognitive Architecture, and Agent 2.0

### Role

Act as a cross-disciplinary principal research scientist spanning:

- AI agents and multi-agent systems,
- compound AI systems,
- mixture-of-experts,
- online learning,
- causal inference,
- uncertainty calibration,
- control theory,
- information theory,
- portfolio theory,
- reliability engineering,
- distributed systems,
- cognitive science,
- organizational science,
- cybernetics,
- economics,
- evolutionary computation,
- digital twins,
- safety engineering,
- human factors.

### Objective

Assess whether the proposed Agent 2.0 / Viable Cognitive Entity architecture represents a meaningful step beyond the standard AI agent abstraction.

The proposed entity combines:

1. SIHRE-style heterogeneous reasoning.
2. Dynamic context-conditioned routing.
3. Adaptive expert trust.
4. Mutable / morphological cognition.
5. Recursive orchestration across Expert -> Agent -> Team -> Army -> Factory.
6. Cognitive portfolio optimization using error covariance.
7. Contextual Bayesian trust.
8. Uncertainty-governed escalation and abstention.
9. Value-of-information based evidence acquisition.
10. Selective verification based on expected risk reduction.
11. Agent self-model / digital twin.
12. Counterfactual simulation.
13. Agent physiology / cognitive homeostasis.
14. Predictive cognitive immunity.
15. Agent KG Mesh / transactive memory.
16. Relationship and complementarity models.
17. Earned autonomy and dynamic authority.
18. Developmental agents / evidence-backed careers.
19. Cognitive genomes, phenotypes, and controlled evolution.
20. System-level temporal evaluation and ablation.

### Primary research questions

#### A. Prior art and novelty
For every concept above:
- What is the closest prior art?
- What terminology already exists?
- Has it been implemented in software or agent systems?
- How close is the proposed design?
- What part, if any, remains potentially distinctive?
- What novelty claims would be unsafe or indefensible?
- What combination-level claim may remain viable?

#### B. Performance hypothesis
For every concept:
- What failure mode of current AI agents could it address?
- Why should it improve performance?
- Under what conditions would it hurt performance?
- What metrics would reveal benefit?
- What experiment could falsify the claim cheaply?

#### C. Mathematical foundations
Identify suitable mathematical frameworks for:
- agent/expert selection,
- correlated failure,
- dynamic trust,
- regime inference,
- disagreement,
- information acquisition,
- verification allocation,
- tail-risk-aware autonomy,
- health control,
- contribution attribution,
- architecture optimization.

Compare alternatives rather than accepting the proposed formula automatically.

#### D. Recursive architecture
Investigate whether a common orchestration abstraction can be reused at:
- cognitive expert level,
- agent level,
- team level,
- army level,
- organizational optimizer level.

Identify:
- invariants,
- level-specific state,
- scaling limits,
- control instability risks,
- communication overhead,
- recursive failure modes.

#### E. Human and real-world transfer
Search biology, cognition, medicine, aviation, military command, emergency response, SRE, high-reliability organizations, economics, ecology, swarm systems, manufacturing, logistics, finance, sports teams, and evolutionary systems.

For each transferable mechanism:
- original mechanism,
- why it works,
- what exact computational analogue could exist,
- what should NOT be copied,
- measurable Agent Factory feature,
- expected benefit,
- evaluation method.

#### F. Architecture synthesis
Propose 3 architectures:
1. minimal viable Agent 2.0,
2. production-grade Viable Cognitive Entity,
3. experimental frontier architecture.

For each give:
- components,
- data model,
- runtime loop,
- governance,
- observability,
- trust update flow,
- failure handling,
- cost controls,
- evaluation plan.

#### G. Research priority
Rank all features by:
- expected impact,
- novelty,
- feasibility,
- engineering cost,
- research risk,
- observability,
- safety value,
- time to first evidence.

### Method constraints

- Prefer primary papers, standards, books, and original system documentation.
- Distinguish established fact from hypothesis.
- Do not equate analogy with implementation.
- Do not assume more agents, more debate, or more complexity improves outcomes.
- Look specifically for negative evidence and failed approaches.
- Flag ideas likely to suffer Goodhart effects.
- Treat system complexity and coordination cost as first-class costs.
- Be conservative about novelty.
