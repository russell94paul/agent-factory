01 — THE CLAIM

Capable was never the problem

A retired agent produced 233 diagnoses, 234 escalations and 0 fixes over 81 days. A separate loop ran 965 times, recorded its own 1.6% success rate, and never adjusted.

Both were capable. Neither was measurable. Everything in this repository exists to make one claim testable — a team of agents did the work, and we can prove it — and, just as importantly, to distinguish that from we could not tell.

That distinction is the product. Most delivery tooling reports green or red. This reports PASS, FAIL, or UNMEASURABLE — and when it scores a recorded run rather than a live one it says so, unprompted, in its own output.

$ python -m factory.certify blueprints/<client>.yaml --calibrate
  [PASS] A8-load-fidelity: emitted == landed == 20
  [PASS] A10-source-agreement: landed == source for 2 key(s)
  [PASS] A12-tenancy-scope: every row within the 2 declared tenant(s)

  scored against corpus <id> — REPLAYED, not a live measurement
02 — THE ORDERING

The order is the design

Six modules, in a sequence that is non-negotiable. Each one is meaningless without the one above it, and the second is the one everybody skips.

ModuleWhat it decidesWhy it comes here
contract.pywhat "done" means, and what "I could not tell" meansEverything downstream is a judgement against this. Nothing can precede it.
evals.pycan the contract actually fail?The negative control. A green suite from an instrument that cannot register failure is the 965-run loop again.
tasks.pywhat a team is doing — append-only, evidence-gatedA terminal verdict must come from history, not from current state.
blueprint.pythe config that is the versionIf the version is a label rather than a hash of the config, two runs can share a version and differ.
deploy.pyput an agent in a repo, boundedBudget caps and a retry ledger, because an unbounded agent re-dispatched all night once.
metrics.pyevery activity metric paired with an outcome metricActivity alone is how a loop records a 1.6% success rate and keeps running.
The rule that enforces it, from the README: "Do not add a team, an optimizer or a UI until pytest tests/test_eval_can_fail.py passes." That test proves the instrument can register a failure. It passes.
03 — HOW IT RUNS

The board is a work queue, not a report

Tickets are not a status display. They are what an agent team claims from. The lane lock is atomic by construction, because two agents taking the same work is the failure that parallelism invites.

Written and unwired is this estate's signature defect. Three independent instances: a deployer with zero callers, a TeamSpec nothing executes, and a guard that depended on a binary that was not installed and so blocked nothing for months. It is invisible to tests, invisible to review, and only a caller-grep finds it. Weight work that wires existing code above work that writes new code.
05 — THE DISCIPLINE

Four rules that produce the rest

1
Name the basis. Every figure is MEASURED, DERIVED, ASSUMED or MARKETED. A vendor claim is never a design premise.
2
Prove the gate can fail. Both directions — it must block bad input and let good work through.
3
Numbers carry their command. A hand-typed count rots invisibly, because it still looks authoritative.
4
Distinguish absent from unmeasured. ZERO, NOT-RECORDED and NOT-VISIBLE are different verdicts.

These are not aspirations. Rule 2 caught its own test suite: the secret scanner refused the commit that introduced it, because a scanner's test fixtures are credential-shaped by design. Rule 3 caught a skills index that claimed 63 files, was corrected to 235, and measured 303 three weeks later — in a file whose own text warns about exactly that.

The honest framing: the instruments are right and the readings are thin. Sensitivity is proved — the contract can fail, and has been shown to. Coverage is not — one recorded run cannot tell a good version from a lucky replay. Growing the corpus comes before any optimiser, or the first optimisation pass drives straight into overfitting and the metric improves while the work does not.

Every figure here was measured on 2026-08-29 and regenerates by command — scripts/export_board.py, workflow-kit/measure.py, python -m pytest -q. Nothing on this page is hand-maintained, because a maintained number rots invisibly and still reads as authoritative.

What this page does not claim. That the platform is finished, that the learning loop works, or that the corpus is broad enough to trust an optimiser. All three are marked DESIGN or n=1 above. The one thing it does claim is that the difference between working and could not tell is visible from the outside — which is the whole point of building it this way round.
