What Delivery #001 teaches Delivery #002

Each lesson carries a baseline and a target, so #002 can be graded rather than described.

L-1 — Shape-matched Findings Preflight — still PROPOSED. ⚠ Partially addressed 2026-08-31: a ticket-keyed RECURRENCE preflight shipped (factory/preflight.py, wired at control.py:485, IMPLEMENTED_NOT_EXERCISED, warn-only, `would_refuse` computed and never acted on). It closes the run-repeats-its-own-failure half. It does NOT close this lesson's half — its lookup is over recorded run verdicts keyed on ticket, and both baseline incidents were interactive work with no ticket and no run. The nine failure families it classifies were clustered from the findings ledger, so the taxonomy is shared even though the lookup is not.

Previous failure evidence existed and later actors did not consume it — eight of thirty-seven issues. In the sharpest case a defect class was fixed in the morning and the identical class was committed against a credential file that afternoon.

Root cause: KNOWLEDGE_AVAILABLE_BUT_NOT_CONSUMED — execution history is stored and not operationalised

Change: A shape matcher at task launch — task shape maps to matching prior findings, and the specific guard is shown AND required. Seed it with three proven shapes: a deny-list over a credential source, a zero from an unproven instrument, an unqualified object reference.

Measurement: Known-failure recurrence rate per mission, split by whether the incident is reachable by the shipped recurrence preflight (a run with a ticket and a verdict) or only by a shape-matched one (interactive work). Reporting one number would hide that the shipped half covers neither baseline incident. · Baseline: 2 (the blind zero and the deny-list). Both are UNREACHABLE by the shipped recurrence preflight. Reachable-by-shipped baseline: 0 of 2."
