## The ordering rules this graph obeys

Three come from the corpus itself, and one is new.

1. **⭐ R17 before R18** — `docs/research/README.md`: *"R18 audits R17's recommendations against our
   code, so running it first throws away the comparison."* The same shape recurs here: **RB-13 must
   run after RB-01 and RB-02**, and for the same reason.

2. **A prompt with no measurement behind it is a wasted run** — `docs/research/R8`'s split into R17
   and R18 happened because *"the filed answer carries zero file paths and zero line references
   against a pack whose own rule demanded both."* So every mission whose questions need a number
   this estate does not yet have is placed **after** the measurement that produces it.

3. **Neighbours must be dispatched together or not at all** — the neighbours table only works if the
   neighbour actually exists to hand a question to. Two pairs below are marked as such.

4. **New here: a `NOT_RESEARCH` item never waits on a research item.** Six of the twenty-six are
   measurements, conversions or decisions. Every one of them is in Wave 0, and none depends on any
   research pass. If they were sequenced behind research, the research would be answering questions
   the measurements would have settled.

## Collision analysis for Wave 1

Ten concurrent passes is only safe if no two would answer the same question. Checked pair by pair
against each mission's `owns` and `must_not_answer`:

| Pair | Risk | Boundary |
|---|---|---|
| RB-01 ↔ RB-16 | ⚠ **Real.** Both touch system decomposition | RB-01 owns the **external** literature; RB-16 owns the **two decompositions already on file here**. RB-01 must not compare our four planes to anything; RB-16 must not survey MAS. |
| RB-02 ↔ RB-12 | ⚠ **Real.** Credit assignment needs trace fields | ⭐ **Dispatch as a pair, RB-02 first.** RB-12 is placed in Wave 2 for this reason. |
| RB-04 ↔ RB-11 | ⚠ **Real.** Both are about whether more than one agent helps | RB-04 owns **topology-task fit from external evidence**; RB-11 owns **error correlation as a composition criterion**. RB-11 must not recommend a topology; RB-04 must not propose a selection mechanism. |
| RB-06 ↔ RB-07 | Low | RB-06 owns **configuration inputs**; RB-07 owns **health outputs**. |
| RB-08 ↔ RB-05 | ⚠ **Real.** Both touch the sandbox | RB-08 owns the **threat model**; RB-05 owns **compensation and rollback**. RB-05 must not evaluate isolation; RB-08 must not design a compensating action. |
| RB-15 ↔ RB-09 | Low | RB-15 owns the **representation** of staged autonomy; RB-09 owns the **protocol** for scoring a candidate. |
| RB-17 ↔ everything | None | It is a vocabulary crosswalk over artifacts that already exist. |
| RB-20 ↔ RB-02 | Low-moderate | RB-02 owns **telemetry**; RB-20 owns **interoperability**. Both could stray into "what standard should we adopt" — each `must_not_answer` names the other's layer. |
| RB-03 ↔ RB-02 | Low | RB-03 owns **what a knowledge store would add**; RB-02 owns **what a run emits**. |
| RB-10 ↔ RB-03 | Low-moderate | Both touch memory. RB-10 owns **near-miss capture as a mechanism**; RB-03 owns **whether a knowledge fabric is needed at all**. |

⚠ **Five pairs carry real collision risk, and none is eliminated by sequencing** — they are
genuinely adjacent questions. The neighbours table is the control, and
`docs/research/README.md` records that it is not a perfect one: it did **not** prevent the alerting
question being answered five different ways across five passes (`absorption-backlog.md` AB-19),
because the neighbours table scopes **subjects** and that question **cut across subjects**.

⭐ **The missing control is a cross-cutting-question register.** Before dispatching Wave 1, write
down the questions that belong to no single pass — *what should be automated, what should interrupt
a human, what counts as evidence, what may be optimised* — and name, for each, which pass owns it or
that none does. That register does not exist and its absence has already cost one reconciliation.

## The honest summary

**If only three things are done, do the Wave 0 measurements** — RB-00A (convert the `.docx`),
RB-00C (one real run) and RB-00D (the two tenancy questions). Between them they:

- make the last 635 KB of the corpus readable, which every deliverable in `docs/_index/` currently

- give **four** Wave-2 missions an outcome variable they do not have;
- and remove the risk that the one calibrated fixture is built on a wrong primary key.

**None of the three is a research mission.** That is the finding this dependency graph exists to
make visible: this corpus holds 26 filed research answers totalling roughly 1.9 MB, plus 19
conclusions nobody actioned, and its binding constraint is measurement, not knowledge.

anything. If RB-00C lands and the first real run behaves unexpectedly — which is what first runs
do — several of these dependencies will be wrong, and the graph should be redrawn rather than
defended.
